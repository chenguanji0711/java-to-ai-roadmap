                                            1. 今天开始，用交付物换掉收藏夹

                                            这节帮你拿回准备方向分：每天结束时，要有代码、测试或一次脱稿讲解留下来。

                                            “学会”是关教程能改需求，关 AI 能解释，弄坏还能定位。目标是争取初筛和技术面试机会，不承诺录用。

                                            主线 16 周，零基础选 24 周，有 Java、SQL 和接口经验才选 8 周。阅读约 25–30 分钟，周表随用随查。

                                            ⚠️
                                            注意周数是训练预算。每周只有 8 小时就拉长日历，别用看完视频冒充完成。先核对招聘窗口、学历和到岗要求，学习不能替代资格。

                                            暂缓组成原理、CSAPP、MIT 6.1810、CS144；删去 JVM 调参、字节码和类加载全流程；不学一致性算法、DDD、微服务全家桶、K8s、消息队列集群。先交付可靠服务。

                                            2. 面试官在寻找哪些证据

                                            这节帮你把“我学过”改成“我能证明”，避免会背概念却接不住追问。

                                            以下是本文评审判断，不是公司打分表；题目是训练问法，不是真实面经原题。

                                            判断面试里怎样留下证据
                                            能否独立完成小需求当场给接口加一个边界校验，解释失败时返回什么。
                                            是否理解因果讲缓存时说出数据库更新后为何可能读到旧值，再给取舍。
                                            是否拥有项目指出自己修过的一个 bug，展示复现条件和回归测试。
                                            能否合作、承担责任不会时说明已知边界和验证步骤，不把 AI 或队友当挡箭牌。

                                            面试间里的一幕：候选人把 HashMap 的扩容讲得很熟，我随口问“你往里面放自定义对象，取出来却是 null，为什么”。他卡住了三秒，说“可能是版本问题”。

                                            不是他不会——是他背的是结论，没碰过因果。我当场让他写 equals 和 hashCode，写完他自己笑了：“原来必须一起重写。”

                                            这也是本文的取舍标准：凡是只能背、不能当场验证的，优先级都往后放。

                                            3. 选一条时间线，每周交三样东西

                                            4. 六个阶段，过出门考再往下走

                                            这节帮你拿基础分：用实验和项目回答问题。

                                            P0写得出，也调得动

                                            这阶段帮你拿编码起步分。为什么学：先能改小程序，才不至于照抄框架代码。

                                            学什么

                                            变量像贴标签的盒子，是保存值的名字。先用循环打印 1 到 10，再改条件，亲眼看输出怎么变。

                                            对象像带操作按钮的资料卡，是数据与行为的组合。List<Student> 里塞自定义类，就是最常见的用法。

                                            接口像插座规格，是调用约定。换实现不用改调用者——这句话在面试里能顶半页纸。

                                            异常像报警，是失败报告机制。写之前先想清楚：哪些输入该拒绝，哪些故障该上抛。

                                            Git 像账本，管版本；Maven 像装配清单，管依赖与构建；测试像验收尺，断言结果符合约定。这三样不用精通，但要跑通一次完整循环。

                                            面试会怎么问：① 给记录加一个字段，要改哪里？② 文件不存在怎么处理？③ 接口与实现拆开有什么收益？④ 如何定位这段空指针？

                                            答不上来会怎样：现场修改卡住，项目代码难以自证。

                                            出门考：不看教程写“文件读入→分类统计→输出”；覆盖空文件、坏数据、重复记录；断点定位一个故意制造的 bug，并讲 3 分钟。

                                            资源：dev.java 读语法、对象、异常。

                                            P1集合、算法与并发的为什么

                                            面试官问「你 HashMap 里放了自定义对象，为什么取不出来」——这一节就是为这一问准备的。为什么学：效率和线程安全会直接影响项目正确性。

                                            学什么

                                            集合像不同的收纳盒：List 保顺序、Set 去重、Map 按键找值。面试时先讲选型理由，再讲代价，别背接口签名。

                                            HashMap 像按门牌分区的快递柜，是用散列定位桶的映射。标准答法：先算桶位置，再比较键；冲突要继续找，扩容有成本。

                                            equals 与 hashCode 是一对——equals 相等的键，hashCode 必须相同。键放进去以后再改参与计算的字段，可能再也找不到它（上面那幕就是这件事）。别只记“要一起重写”，要能说出为什么。

                                            复杂度像估算“人数翻倍后排队要多久”，是规模与计算量的增长关系。先给朴素解，再说怎么减少重复工作；写完补上空输入、重复值、边界三组测试。

                                            线程像同时办事的工人，共享内存但各有执行路径。锁像厕所门栓，保证临界区互斥；volatile 像及时更新的公告栏，管可见性和顺序，但不能把 count++ 变原子——这句话答错，后面全垮。

                                            线程池像有候客区的窗口，复用线程、排队管理任务。沿着“核心线程 → 队列 → 最大线程 → 拒绝策略”回答；无界队列可能把内存吃光。容量按耗时、阻塞比例和实测来定，不是线程越多越快。

                                            面试会怎么问：① HashMap 冲突后怎么找？② 复合操作用了并发 Map 就安全吗？③ volatile 为什么防不住丢计数？④ 队列满了会怎样？⑤ 这题能少遍历一次吗？

                                            答不上来会怎样：缓存键和并发请求讲不清；手撕换边界就出错。

                                            出门考：画一次冲突与扩容；复现计数竞争并用锁修好；制造线程池拒绝；30 分钟独立写一道练过的中等题、解释复杂度并补边界测试。

                                            资源：线程池 API 查排队；Hello 算法 按周表选题。

                                            P2MySQL 和 Redis：数据不能靠祈祷

                                            「这条查询为什么慢？」——学完这节，你能在面试现场打开 EXPLAIN 当场回答。为什么学：能返回不代表查得快、写得对。

                                            学什么

                                            索引像书的目录，用来加速定位。回答时讲联合索引的列顺序为什么这么排，再用 EXPLAIN 把扫描行数摆出来——别说“加了索引就快”，那是外行话。

                                            B+ 树像多层目录，叶子节点相连，所以范围查询也快；代价是空间和写入维护。

                                            覆盖索引像目录里已经把答案写全了，不用再翻正文；回表就是拿着主键回去取整条记录。面试官爱听这个对比：“只查索引内的列”和“多查一个非索引列”分别多少行。

                                            事务像一次成套转账，要么一起提交、要么一起回滚。隔离级别规定并发事务能看见什么。MVCC 像文档的历史版本，按可见性规则给你一个“快照”。用两个连接做实验，分清快照读和锁定读——别背“RR 永不幻读”，那句话经不起追问。

                                            缓存像桌边便签，是数据库之外的快速副本。穿透是查不存在的数据，可用短期空值缓存并限制滥用；击穿是热点失效，可合并并发回源；雪崩是大量缓存同时失效或服务故障，要错开过期并限流降级。

                                            数据库写完再删缓存仍有竞争窗口，不能承诺强一致。回答要说允许多旧、过期如何兜底；订单状态等关键判断回数据库核实。Redis 停机时全量回源也可能压垮数据库。

                                            面试会怎么问：① 联合索引为什么这样排列？② 执行计划怎么看？③ 转账中途失败会怎样？④ 缓存三种故障有什么不同？⑤ 数据更新后仍读到旧值怎么办？

                                            答不上来会怎样：优化无依据，重复写入和脏数据兜不住。

                                            出门考：造足以比较差异的数据，保留索引前后计划；双连接复现回滚与锁等待；模拟热点失效和 Redis 不可用，验证接口有超时与降级。

                                            资源：MySQL 索引手册 对照自己的 SQL；Redis 键与过期 用来做失效实验。

                                            P3HTTP、Spring 与排错

                                            项目深挖十有八九从「这个接口怎么工作」开始，这节让你能一路讲到数据库。为什么学：项目深挖通常从“这个接口怎么工作”展开。

                                            学什么

                                            HTTP 像业务信件，是应用层的请求/响应协议；TCP 像带编号和确认的运输通道，保证可靠有序的字节流。握手负责建连和确认初始序号，挥手关闭两个方向——报文可能合并，这也是为什么抓包时看到的时序和你以为的不一样。

                                            字节流没有消息边界，得靠长度或分隔符切分。HTTP 本身无状态，登录靠 Cookie 带会话标识；HTTPS 在中间加一层 TLS 保护传输。

                                            认证和授权要分清楚：认证是“你是谁”，授权是“你能看谁的资料”。顺带答一句“超时重试为什么可能重复写”——很多人只会说“要幂等”，说不出为什么。

                                            IoC 像食堂统一配餐：容器创建、管理对象并注入依赖。AOP 像门口统一查票：在业务调用周围织入通用逻辑。回答时画一条 Controller → Service → 数据库，把校验、事务、异常处理标在正确的位置上。

                                            事务代理像必须经过的验票口。默认代理模式下：同类内部自调用会绕过代理；吞掉异常可能让代理无法按预期回滚；默认回滚规则也不覆盖所有受检异常。结论：“加了注解” ≠ “事务生效”。

                                            JVM 像车间：堆里放对象，栈里存调用帧，GC 回收不可达对象。练的是排查路径——CPU 高查忙线程，内存涨查对象保留，响应慢查依赖。先留证据，再改参数。

                                            面试会怎么问：① 请求超时能直接重试吗？② TCP 为什么要确认序号？③ IoC 与自己 new 有何区别？④ 自调用事务为何没生效？⑤ CPU 高时先看什么？

                                            答不上来会怎样：能背注解却不能定位异常；权限或事务漏洞会削弱整个项目的可信度。

                                            出门考：交付校验、分页、登录和所有者检查；证明用户甲不能读乙的资料；写事务回滚集成测试；用线程转储定位一个自造忙循环。

                                            资源：MDN HTTP 看报文；事务注解说明 核对代理与回滚。

                                            P4AI 应用：先检索，再证明有效

                                            这阶段帮你避免把“接过模型接口”写成 AI 工程能力。为什么学：投 AI 应用岗要证明质量、失败处理和成本控制。

                                            学什么

                                            RAG 像开卷考试：先检索资料，再让模型照着答。面试要能区分两种失败——“找错了资料”和“资料对了但答错”，因为改法完全不同。

                                            Embedding 像给文本画语义坐标，把内容变成向量。记住一句：向量相近不等于事实正确。

                                            Prompt 工程像写任务委托书：讲清输入、约束、示例、输出格式，然后用同一批题迭代。面试时展示“我改了什么、同一批题的结果怎么变”，而不是背万能咒语。

                                            Agent 像会自己决定下一步的助手：模型参与决定调什么工具、走哪条路。但固定流程通常更容易测——所以要能回答“为什么这里真的需要自主选择”，以及步数上限、超时和失败出口在哪。

                                            MCP 像统一插口，是连接 AI 应用与工具、资源的协议。它不自动给权限，也不是 Agent 的别名。面试要说明：工具参数校验、访问控制、敏感操作二次确认，分别在哪一层做。

                                            评测像固定试卷，用同一把尺子比较系统。标 20 条：正常 / 无答案 / 歧义 / 越权 / 诱导指令，各 4 条；记录资料命中、引用支持、是否拒答、耗时。另外留一批没见过的题做验收——只优化见过的题，等于背答案。

                                            面试会怎么问：① 没检索到和模型胡答怎么区分？② 分块变大有什么代价？③ 引用存在就算答对吗？④ 为什么不用固定流程？⑤ 恶意文档让工具导出数据怎么办？

                                            答不上来会怎样：项目像接口包装；“准确率高”没有口径就不构成证据。

                                            出门考：同一份非敏感资料跑关键词检索基线与一次改进；保留逐题结果及失败原因；展示无依据拒答和越权阻断。没实调模型时标“模拟响应验证”，不能把它当效果评测。

                                            资源：Spring AI 学接入；MCP 区分各角色。框架只学一个。

                                            P5项目交付与面试表达

                                            面试官不会替你从仓库里找贡献——这节教你把贡献摆到台面上。为什么学：面试官不会替你从仓库里找贡献。

                                            学什么：复现说明像菜谱，让别人得到同一结果；回归测试像修桥后复检，检查修复是否破坏原行为。回答要串起需求、实现、测试与证据。

                                            面试会怎么问：① 哪部分由你负责？② 为什么没选另一种方案？③ 指标如何测？④ 今天需求变了你改哪？⑤ 让别人运行需要几步？

                                            答不上来会怎样：技术栈越多，无法自证的漏洞越多。

                                            出门考：从空环境按说明运行；5 分钟脱稿介绍；接受第 5 节十轮追问；简历每条都能定位到代码、测试或记录。

                                            资源：用 Git Book 整理可读的修改历史。

                                            5. 一个项目，讲五分钟，追十轮

                                            项目不是讲出来的，是「跑得起来 + 说得清」证明出来的。

                                            做“带权限的资料库”：保存、分类、检索资料。后端方向做可靠查询与缓存，AI 方向在同一服务上加带引用问答。

                                            幂等像快递单号，重扫不应重复发货；定义是重复请求不额外改变结果。回答用户范围内的请求标识、唯一约束、重复响应和过期规则，别只放个内存标记。

                                            迭代完成标准
                                            能用资料新增、分页、分类可演示；非法输入有稳定错误响应。
                                            可靠登录、所有者检查、事务和重复提交都有失败测试；日志能关联一次请求。
                                            可交接有启动步骤、配置占位符、测试命令、限制说明和短演示；没有密钥与个人资料。

                                            P95 像排序后靠后的等待时间，是 95% 请求不超过的延迟分位数。报告写机器、数据量、并发、预热、时长和错误率；本机实验别写“生产级”。

                                            五分钟练习预算：半分钟讲痛点，一分钟画路径，一分半讲难点，一分钟讲测试与指标，一分钟讲局限和下一步。

                                            十轮追问按因果走：① 谁使用？② 数据怎么存？③ 为什么选这张表？④ 为什么这个索引？⑤ 缓存旧了呢？⑥ 两次提交呢？⑦ 他人越权呢？⑧ 依赖超时呢？⑨ 测试怎么证明？⑩ 不用当前方案还有什么选择？

                                            面试间里的一幕：候选人讲了四分钟项目，从「微服务架构」讲到「智能中台」。我插一句：「这个接口慢的时候，你先看什么？」

                                            他沉默五秒：「看监控。」

                                            我换个问法：「假设没有监控，你手上只有 EXPLAIN 和日志，你干嘛？」——他答上来了，而且答得很好。可惜前四分钟已经浪费了。

                                            结论：面试官不关心你用了多少技术，只关心出事时你知不知道往哪看。所以叙述顺序应该是：痛点 → 一次真实故障 → 你怎么定位 → 改了什么 → 指标变化。

                                            反例：“高并发智能中台，性能提升 90%。”却说不出负载与原始数据。改写为“比较资料分页索引前后执行计划，保留复现步骤”，实测后再填结果。

                                            6. 一页简历与 JD：关键词必须带证据

                                            这节帮你减少初筛信息缺失，不能绕过资格要求。

                                            初筛像配零件，判断经历是否符合岗位。学历、专业、毕业时间、实习时长、到岗时间可能是硬条件；关键词帮助检索和阅读，不同团队权重不同，没有保证通过的公式。

                                            一页按“联系与方向→教育与到岗→经历／项目→技能证据”排。有相关实习优先展示，无实习就突出项目；成绩、排名只写真实相关的，不伪造学历与工作量。

                                            姓名｜求职：Java 后端实习｜联系方式
学校／专业／毕业时间｜可到岗日期／每周天数／连续月数
项目：服务谁、解决什么问题（两行以内）
贡献：问题 → 我的动作 → 测试或实测结果 → 证据入口
技能：能用 HashMap 分析查找，能用 EXPLAIN 验证索引等
仓库或演示：可访问入口；保留运行说明，不含密钥

                                            反例：“熟悉 Java、MySQL、Redis”。改为“实现用户隔离接口，验证越权、回滚和重复提交”。个人项目别写成企业任职。

                                            JD 像采购清单，是岗位职责与条件说明。本文无全市场统计，不把某词一概当凑数；看实际交付要求，再看“了解／优先”。

                                            关键词怎样判断是否要重点准备
                                            RAG要做知识库就准备切分、召回、引用与失败分析；只列词时问清任务。
                                            Agent要做多步任务就准备状态、失败恢复和上限；解释固定流程是否够用。
                                            MCP要接工具就准备协议角色、权限与参数校验，不堆服务。
                                            评测要改善效果就拿出逐题结果、标注标准与对照。
                                            Prompt 工程要稳定输出就准备格式验证、失败样例与回归，不比谁提示长。

                                            投递记录不是给 HR 看的，是给你自己复盘用的。没有记录，你的复盘就只是在猜。

                                            日期公司/岗位简历版本结果下一步
                                            例：10-20A 厂 · Java 后端实习v2（突出索引优化）简历挂核对 JD 是否要求学历/到岗
                                            例：10-23B 厂 · AI 应用实习v3（突出评测）一面挂 · 问倒 RAG补「检索失败 vs 生成失败」

                                            投递表记岗位、资格、关键词、简历版本、日期与反馈。没回复先查匹配度；技术面反复失败再分类补课。

                                            7. 面试流程：把时间花在能验证的地方

                                            面试只有一小时，这节教你把一小时花在能被验证的地方。

                                            实际轮数与顺序因岗位而异，八股与手撕无统一比例。60 分钟模拟可分：介绍 3 分钟、项目 20 分钟、基础 12 分钟、编码 20 分钟、反问 5 分钟。这是练习建议，不是统计。

                                            介绍讲身份、可实习多久、做过什么、值得追问哪个点。例：“我的资料库处理了重复提交与缓存失效，有失败用例，可以展开。”没做过就别照念。

                                            八股讲类比、定义和实验；手撕确认输入输出和边界，给朴素解与优化，再编码测试。不确定就提出反例验证，别编结论。

                                            反问：“实习生前四周交付什么？”“谁负责评审和测试？”“更看重检索效果还是后端可靠性？”让回答帮助你选岗位。

                                            8. AI 协作：用过工具，也要拥有代码

                                            这节帮你保住可信度：AI 生成的代码也要能解释。

                                            Vibe coding 像让助手按口述搭积木，用自然语言推动代码生成。原型可以快；进项目要 review、测试、验证依赖。这是分工建议，不是团队制度统计。

                                            面试会检查理解与验证。提交的每一行都应能解释目的、输入输出、失败条件与替代方案；不要求背第三方库源码。

                                            面试官真正怕的不是你用 AI，而是你说不清为什么这么写——因为那意味着线上出事时，你修不了。

                                            你定验收→AI 给小步方案→你看 diff→跑测试→独立改需求。Review 像交稿前审阅，核对变化与需求；测试只覆盖设计过的情况，不失败不等于无缺陷。

                                            需求：给我的资料接口增加重复提交保护。
先指出现有调用路径与不确定之处，不要直接大改。
给两个方案，说明并发、过期和失败重试的差异。
我选定方案后，只改必要部分，并列出可复现的失败测试。
不要读取或输出密钥，不要添加未核实的依赖。
完成后逐段解释；由我独立修改一个边界场景再验收。

                                            问清获准工具、数据能否外发、谁 review、必过测试。内部代码、用户资料与凭据按团队规则处理，提交者仍对缺陷负责。面试用 AI 先获允许。

                                            被问穿时：“初稿由 AI 生成，我验证了这些路径；这里理解不够，我给一个可解释的简化方案。”面后删掉无法自证的表述，补测试、独立重写核心。

                                            验证后才打勾。进度保存在本浏览器，与长线版分开；投递前重新抽测。

                                            10. 常见死法：失败要能定位

                                            这节帮你止损：把拒绝变成能修的缺口。

                                            失败表现下次行动
                                            学了一堆却没有能运行的项目暂停新课，先交一条从请求到数据库的完整路径。
                                            项目讲架构，追问只说“框架帮我做了”选一条请求画调用路径，逐层做一次失败实验。
                                            刷题只记答案，换输入就错先手推边界，再关答案重写；记录识别特征和反例。
                                            简历写满 AI 名词，没有效果证据删除未做内容，补同一题集上的对照与失败样例。
                                            不会却硬猜，越答越矛盾明确已知与未知，提出最小验证步骤。

                                            这节帮你避免版本混用；运行依赖以实际项目为准。
